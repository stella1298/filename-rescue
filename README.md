# filename 평가 데이터셋

영상 17개와 영상별 정답 JSON 17개를 담았습니다. 원본 파일명과 영상 내용은 그대로 유지했습니다. 전체 영상 용량은 약 593.5MiB입니다.

## 폴더 구조

```text
evaluation/
  images/                 # 사진 추가용, 현재 비어 있음
  videos/                 # 원본 MP4 17개
  answers/                # 영상 파일명과 같은 이름의 JSON 17개
  manifest.json           # 원본 해시·길이·크기·초안 작성 시점 기록
```

예를 들어 `videos/12344963_1920_1080_25fps.mp4`의 정답은 `answers/12344963_1920_1080_25fps.json`입니다. 영상 한 편당 정답 하나를 사용합니다. 프레임은 평가 코드가 추출합니다.

## 정답 수정 방법

각 JSON에는 `keywords`, `reason`, `place_name` 세 항목만 있습니다.

- `keywords`: 관찰되는 대상·활동·배경과 허용할 동의어입니다. 개수 제한은 없으며, 모델 출력의 최대 5개 제한과는 별개입니다.
- `reason`: 태그를 뒷받침하는 관찰 근거와 주요 행동 변화입니다. 1~120자로 작성합니다.
- `place_name`: 화면에서 정확한 고유 지명을 확인할 때만 작성합니다. 현재는 모두 `null`입니다.

태그는 **AI assistant가 영상별 8개 시점의 프레임을 확인해 작성한 초안**입니다. 모든 순간이나 음성을 검토한 정답은 아닙니다. 팀에서 원본 영상 전체를 보고 태그·근거를 수정한 뒤, 전부 검수했을 때만 `manifest.json`의 `human_reviewed`를 `true`, `annotation_status`를 `reviewed`로 바꾸세요. 실제 확인한 시각은 각 파일의 `observed_timestamps_s`에 기록했습니다.

허용 태그 일치율은 참고값으로 사용하고, 최종 품질은 사람이 정확성과 파일명 활용도로 평가합니다. 비교 실험을 시작하기 전에 정답을 확정하고 모든 조건에 같은 버전을 사용하세요.

## 평가 코드에 연결하기

[filename-model-quality-bench](https://github.com/yooongZa/filename-model-quality-bench)의 데이터 루트로 이 저장소의 `evaluation` 폴더를 지정합니다.

```bash
# filename-model-quality-bench 폴더에서 실행하는 예시
python a_quality.py --dataset-root ../filename-rescue_fork/evaluation --frames all --dry-run
```

`--dry-run`은 원본 영상에서 프레임을 준비하고 입력과 요청 수를 검사합니다. 모델을 다운로드하거나 추론하지 않습니다. 생성되는 `.filename_frames/` 캐시는 Git에서 제외합니다.

Colab에서는 `evaluation` 폴더를 `evaluation.zip`으로 압축해 Google Drive의 `filename/datasets/`에 넣습니다. 사진을 추가할 때는 `images/`에 사진을 넣고 `answers/`에 같은 이름의 JSON을 작성하세요. 사진과 영상 사이에서도 확장자를 제외한 파일명이 중복되지 않아야 합니다.

검증: 영상 17개와 JSON 17개의 일대일 대응, JSON 필드·자료형·태그 중복·근거 길이, 원본 복사본의 SHA-256(해시) 일치를 확인했습니다. 기존 평가 코드의 `--frames all --dry-run`에서 영상 17건과 자동 추출 프레임 40장을 정상 인식했습니다. 실제 모델 추론은 실행하지 않았습니다.

Based-On: none — LMS Dataset 예제는 확인했으나 이 영상·정답 파일 배치에 직접 대응하지 않아 기존 filename 평가 코드의 입력 규약을 따랐습니다.
