# filename-rescue : 파일명 구조대 평가 데이터셋

사진 · 영상의 내용을 로컬 AI 모델로 분석해 파일명에 태그를 붙이는 프로그램 **filename(팀명 파일명 구조대)** 의 품질을 재기 위해 만든 **평가 데이터셋**입니다. AIFFEL EPA 1기 DLthon(2026.10)에서 4인 팀의 데이터 담당으로 만들었습니다.

```text
IMG_001.jpg → IMG_001__해변_자전거_도로_라이딩_야외.jpg      ← 프로그램이 하는 일
images/i01.jpg + answers/i01.json                           ← 이 저장소 : 그 결과를 채점할 정답
```

- 프로그램 : [yooongZa/filename](https://github.com/yooongZa/filename)
- 평가 코드 : [yooongZa/filename-model-quality-bench](https://github.com/yooongZa/filename-model-quality-bench) (이 저장소의 `evaluation/`을 데이터 루트로 지정)

## 들어 있는 것

| 구분 | 수량 | 위치 |
|---|---:|---|
| 사진 | 20 | `evaluation/images/` (`i01.jpg` – `i20.jpg`) |
| 영상 | 20 | `evaluation/videos/` (`v01.mp4` – `v20.mp4`) |
| 정답 | 40 | `evaluation/answers/` (사진 · 영상과 같은 ID의 `.json`) |
| 매니페스트 | 1 | `evaluation/manifest.json` |
| EDA 그래프 | 4 | `evaluation/assets/` |

- **사진 해상도 (짧은 변)** : 1,000 – 1,999px 5장 · 2,000 – 2,999px 5장 · 3,000 – 3,999px 6장 · 4,000px 이상 4장 (매니페스트의 실제 크기 기준. 팀 발표 자료의 6 · 4 · 7 · 3장은 다른 표에서 다시 집계한 값)
- **영상** : 길이 6.63 – 52.48초(중앙값 15.86초), 짧은 변 1,080px 8편 · 1,440px 1편 · 2,160px 11편
- **정답** : 허용 태그 · 관찰 근거 · 장소 (아래 '정답 형식')
- **매니페스트** : 40개 파일의 크기 · SHA-256 · 해상도(영상은 길이 · fps). 원래 파일명과 관찰 시점은 영상 v01 – v17만
- **EDA 그래프** : 사진 · 영상 해상도, 영상 길이, 키워드 빈도

주제는 여행 · 야외 활동 · 일상 장면입니다(등산, 공항, 지하철, 시장, 스키, 수영, 요리, 고양이, 서핑, 피크닉, 패러글라이딩 등).

## 정답 형식

```json
{
  "keywords": ["등산", "산행", "트레킹", "하이킹", "등산 스틱", "트레킹 폴", "..."],
  "reason": "배낭과 등산 스틱을 든 사람들이 풀과 바위가 있는 산길을 따라 위쪽으로 걸어갑니다.",
  "place_name": null
}
```

| 칸 | 뜻 |
|---|---|
| `keywords` | **허용 태그 목록.** 모델은 태그를 최대 5개 내는데, 그중 몇 개가 이 목록에 들어 있는지를 봅니다. 그래서 동의어 · 표현 변형을 넓게 넣었습니다(파일당 16 ~ 42개). 정답 개수가 아닙니다 |
| `reason` | 태그를 뒷받침하는 관찰 근거 (120자 이내) |
| `place_name` | 화면에서 고유 지명을 확실히 알 수 있을 때만. 아니면 `null` |

**왜 '허용 태그'인가** : 같은 장면을 '등산'으로도 '트레킹'으로도 부를 수 있습니다. 정답을 하나로 정하면 맞는 답도 틀린 것으로 채점됩니다. 그래서 정답은 '허용되는 표현의 집합'으로 두고, 태그 일치율은 참고값으로 씁니다. 최종 품질은 사람이 태그 정확성과 파일명으로서의 쓸모를 함께 봅니다.

### 채점 방법 (발표 기준)

모델이 낸 태그 중 허용 목록에 든 비율, 즉 **허용 목록 기준 정밀도(Precision)** 를 씁니다.

```text
출력 태그 : 줄다리기 · 사람들 · 야외 · 현수막 · 군인
허용 목록에 있음 : 줄다리기 · 사람들 · 야외 · 현수막   → 4 / 5 = 80%
```

| 지표 | 판정 기준 | 사용 |
|---|---|---|
| Precision | 출력한 태그 중 허용 태그 | 사용 |
| Recall | 필수 태그 중 몇 개를 맞혔나 | 따로 재지 않음 (허용 목록은 정답 개수가 아님) |
| Accuracy | 전체 태그 후보의 정오 | 사용 안 함 |

핵심 키워드를 빠뜨리는 문제(재현율)와 검색 활용성은 사람 평가로 보완했습니다.

## 이 데이터로 한 실험 (팀 발표, 2026.10.19)

같은 40개 파일로 설정을 하나씩 바꿔 가며 비교했습니다. 모델은 Gemma 4 12B IT QAT Q4_0(llama.cpp), temperature 0, seed 고정입니다.

**RTX 4060 8GB : 실행 범위 찾기** (40개 × 설정 19개 = 요청 640회)

| 결과 | 값 |
|---|---|
| 응답 완료 | 640 / 640 (실행 오류 · 타임아웃 0) |
| 기준 설정의 원문 JSON 통과 | 30 / 40 (사진 18/20 · 영상 12/20) |
| 영상 프레임 1 · 3 · 5장 | 원문 JSON 통과 14/20 · 12/20 · 2/20 (프레임이 늘면 형식 통과 하락) |
| GPU 적재 30 → 34층 | 처리 시간 약 19% 단축 (사진 11.8 → 9.6초, 영상 14.6 → 11.8초) |

**RTX 3070 8GB : 13개 조건의 태그 비교 → 프로그램 설정 R13**

| ID | 짧은 변 | 비전 예산 | 방식 | 평균 초 | VRAM MiB | 점수 |
|---|---|---|---|---|---|---|
| R11 | 720 | 280 | 단일 | 10.72 | 7,159 | −3 |
| R12 | 360 | 560 | 단일 | 9.98 | 7,156 | −5 |
| **R13** | **720** | **560** | **단일** | **11.06** | **7,180** | **+15** |
| R17 | 720 | 560 | 2단계 · 5태그 | 24.17 | 7,267 | +13 |
| R05 | 480 | 140 | 단일 · 추론 ON | 76.74 | 6,911 | −4 |

- 점수는 사용자가 결과 표에 표시한 합계(맞으면 +1, 틀리면 −1)
- 프로그램 적용 설정 : 짧은 변 720px, 비전 예산 560, 영상은 길이의 20% · 50% · 80%에서 최대 3장, 단일 프롬프트, 추론 OFF
- 실제 변경 예 : `v04.mp4` → `v04__줄다리기_운동회_야외_사람들_단체 활동.mp4`

**한계 (팀 회고)** : 설정 선택과 평가에 같은 40개를 반복해서 썼고 검수자는 1명이었습니다. 동의어가 허용 목록에서 빠지면 일치율이 떨어졌습니다. 다음에는 채점 기준과 합격선을 먼저 정하고, 새 자료와 복수 평가자로 따로 검증해야 합니다.

## 바로 쓰기

데이터셋과 평가 코드를 같은 폴더에 나란히 받은 뒤, 평가 코드 폴더에서 실행합니다.

```bash
git clone https://github.com/stella1298/filename-rescue.git
git clone https://github.com/yooongZa/filename-model-quality-bench.git
cd filename-model-quality-bench
python a_quality.py --dataset-root ../filename-rescue/evaluation --frames all --dry-run
```

- `--dry-run` : 프레임 준비와 입력 확인까지. 모델은 받지도 돌리지도 않습니다
- 영상 프레임은 평가 코드가 추출합니다(`.filename_frames/` 캐시는 커밋하지 않음)
- 코랩 : `evaluation/`을 `evaluation.zip`으로 묶어 Drive `filename/datasets/`에 올림
- 저장소 크기가 약 800MB(영상 678MB)라 받는 데 시간이 걸립니다

자세한 설명, EDA 그래프, 영상별 대표 태그는 [evaluation/README.md](evaluation/README.md)에 있습니다.

## 만든 방법

1. 여러 데이터셋 라이브러리를 검토하고, 해상도 실험과 다양한 촬영 상황에 맞춰 **직접 골랐습니다**. 기준은 고해상도 원본, 사진과 영상(정지 장면과 시간에 따른 행동 변화), 다양한 배경 · 활동(실내 · 야외, 이동 · 운동 · 일상)입니다. 같은 원본을 720 · 480 · 360px로 줄여 해상도 조건을 비교할 수 있도록 고해상도 원본 위주로 골랐습니다.
2. 파일마다 **내용과 무관한 이름**(`i01`, `v01` …)을 붙였습니다. 프로그램이 풀려는 문제가 `IMG_001.jpg` · `DJI_0001.MP4`처럼 내용을 알 수 없는 파일명이어서, 그 상황을 흉내 내려는 것입니다. 이렇게 하면 모델이 파일명에서 힌트를 얻지 못하고 화면 내용만 보고 태그를 만듭니다. 40개 파일 모두 크기 · SHA-256 · 해상도(영상은 길이 · fps)를 매니페스트에 기록했고, 영상 v01 ~ v17은 원래 파일명도 남겼습니다. 원본 내용은 바꾸지 않았습니다.
3. 영상은 8개 시점(3% ~ 96%)의 프레임을 보고 정답 초안을 만들었습니다. 실제로 본 시각은 `observed_timestamps_s`에 남겼습니다.
4. 이미지 · 영상과 정답의 일대일 대응, JSON 칸 · 자료형 · 태그 중복 · 근거 길이, 해시 일치를 확인하고, 평가 코드의 `--dry-run`에서 40건이 정상 인식되는 것을 확인했습니다.

## 검수 상태와 한계

- **정답은 AI 도움으로 만든 초안입니다.** 사람이 원본 전체를 검수한 상태가 아닙니다(`manifest.json` : `human_reviewed: false`, `annotation_status: draft`). 영상은 8개 시점만 봤고 음성은 분석하지 않았습니다.
- 평가에 쓰기 전에 원본을 보고 정답을 확정하고, **모든 실험 조건에서 같은 정답 버전**을 쓰세요.
- 사람이 실제로 검수한 파일만 `human_reviewed: true`, `annotation_status: reviewed`로 바꿉니다.
- 40개는 모델을 고르고 설정을 비교하는 데 쓰는 작은 세트입니다. 학습용이 아닙니다.
